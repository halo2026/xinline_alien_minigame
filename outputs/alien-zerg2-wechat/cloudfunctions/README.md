## 开通和部署

1. 使用异星要塞 AppID wx290826620512561a 打开微信开发者工具，点击云开发，按控制台提示开通并创建环境。套餐与费用由账号所有者选择。
2. 在云开发控制台复制环境 ID，填写 shared/cloud-config.js 的 env。不能使用另一个 AppID 的环境。
3. 云数据库创建集合 player_saves_v1。权限设为所有客户端不可读、不可写（自定义规则参考 database.rules.json）。客户端只能通过云函数读取自己的档案，云函数从 getWXContext 获取 OPENID/APPID，不能相信请求传来的微信 ID。
4. 右击 cloudfunctions/player-save，选择“上传并部署：云端安装依赖”。云函数使用 wx-server-sdk，当前环境初始化；无需在小游戏中放密钥。
5. 执行 python3 tools/package-game.py，然后编译、真机验证。客户端云存档模块放在 defense-code 分包；启动会先完成分包加载，再连接云端。
6. 通过下方验收后再上传并设为体验版。不要清理现有手机数据。

## 同步行为

- 云端按 AppID + OPENID + 存档区的 SHA-256 标识隔离账号。手机使用 phone-v1 存档区；开发工具通过 getDeviceInfo().platform 识别并使用 simulator 区，测试档不会抢占手机首次旧档迁移。开发版和体验版配置相同环境时共享该账号的档案。
- 同步完整进度对象：等级、经验、装备、仓库、科技、资源、任务首次通关奖励、待揭晓开箱结果、每幕检查点、步行模式、最近战役。屏幕方向仍是设备偏好。
- 首次启用云存档：云端无档时迁移本机旧档；云端有档时优先云端，本机旧档留备份。新手机读取云端。
- 战斗位置、怪物、子弹不保存；换机从最近战役的当前幕开始。狼关依照现有流程，不新增幕存档。
- 本机变更先落盘，约 1.5 秒合并上传；切后台尝试立即上传；前台每 30 秒检查其他设备更新。系统杀进程不保证后台请求完成，未发送操作会留在本地待重试。
- 冷启动必须联网确认账号与云版本后进入；已进入游戏后断网，可继续并缓存变更。另一手机只能读取已成功同步的进度。
- 写入有修订号检查和幂等操作 ID。离线分叉不能叠加货币/物品，冲突时备份本地后读取云端；不按手机时钟覆盖。
- 本地云档缓存：原 KEY + :cloud-v1；冲突备份后缀 :backup；换账号备份后缀 :account-backup。各保留最近一份，原本地 KEY 不清理。
- 手动清空客户端数据不会删除云档；之前通过改 KEY 清零的方式不再适用于云端，需要另行设计账号重置。

## 必须进行的真实验收

A 手机旧存档首次迁移 → 改装备/花费资源/过第一幕 → 等待同步 → B 手机同微信读到一致进度且进入第二幕。不同微信必须新档。A 离线修改，B 在线修改，再连 A 应提示冲突且不覆盖 B。模拟云端写成功但客户端丢响应，重进不得重复奖励。体验版与开发版都验证一次。

本地 11 项存档测试通过。真实云函数已返回 simulator 存档 revision 146、level 4，手机区返回空存档，验证了服务器读取、持续写入/事务更新和模拟器隔离；两台手机尚未验证。云存档不是反作弊服务器：装备/奖励/货币仍由客户端计算，商城仍模拟支付；正式收费前必须接入服务器订单核验与货币流水，不能把客户端提交的余额当成付款依据。
