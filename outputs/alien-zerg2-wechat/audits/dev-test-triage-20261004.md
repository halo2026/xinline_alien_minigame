## 已修复的真实问题

主关卡 `shared/view.js` 的图片加载器直接 `resolve(image)`。当原生图片代理具有 `then` 方法时，Promise 将调用它并持续等待，导致加载卡住。现在通过 `{image}` 包装后再汇总还原原对象，与狼关现有方式一致。

新增 `image-loader.test.js` 验证两关的原生代理对象、对象身份、进度计数及错误文件名。原 `core.test.js` 中图片加载用例也恢复通过。此前被连带取消的手雷用例现在执行并暴露断言差异，所以失败数从 221 变为 222，并非新增回归；取消数从 2 变为 0。

主包只剩 1,889 字节余量的问题通过新增 `level-code` 数据分包解决，现余约 975 KiB。字节一致性、导出一致性、两关启动及全部原有资源校验通过。重复构建清除旧生成文件的检查也通过，微信模拟器重新编译后进入第一关。

## 已辨认的失败来源

- `page.test.js`：访问未提交的旧小程序 `miniprogram/pages/index/index.js`。当前产品入口是小游戏，不应为了这个历史入口更改运行代码。
- `app-resume.test.js` 的原生循环用例：截取源码到 VM 后没有提供当前代码需要的 `cloudStore`，属于测试上下文缺失；同文件其他断言还需单独检查。
- `minigame.test.js`：旧 mock 未提供 `renderBudget.pixelRatio`，并仍检查已不存在的 `flipLandscape`；应更新为当前分包加载、触控与前后台契约。
- 多个绘制用例：简化 Canvas mock 缺少 `createRadialGradient`、`addColorStop`、`translate` 等当前绘制接口。应补全测试环境或使用已安装的真实 Canvas 后再分析断言。
- `core.test.js` 的连续投雷断言：默认装备经 `vehicle-gear.js` 赋予装填器双雷能力，旧用例假设第二次投雷立即受冷却限制。需要显式构造无装填器的单雷场景，不能直接削弱实际装备能力。
- `progression.test.js` 的损坏存档回退断言：当前实现抛出 `PROGRESS_LOAD_FAILED` 来保留原进度，旧测试期待静默新建存档。应结合存档安全测试更新历史预期。

这些是部分已核查的来源，不能据此把所有失败归为旧测试。JSON 中错误类型统计仅用于定位；剩余战役波次、掉落、装备和交互断言仍需逐项对照当前设计。
