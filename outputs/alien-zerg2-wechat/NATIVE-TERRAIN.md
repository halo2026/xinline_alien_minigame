# 原生地形拼接与扩图

依据 source-map/yxys_zerg_002.ter、原版 terrain/t_04.png、t_05.png、t_06.png、alpha01.png 和既有 extract-source.py 解码规则。

TER 文件24字节头：小端4个short、4个int，标志0x66、版本1、格宽格高。后续每格x/y(short)、层数(byte)，每层材质ID与角掩码两个byte。地形格64×64。四角权重左上8、右上4、左下2、右下1，掩码1—15。512×256材质图左半按掩码选过渡块，右半为4×4全覆盖变化块。原生材质已包含过渡alpha，无须另画道路描边。

本次将路线距离场采样到格点，按角状态拼接4号地表、5号路肩、6号道路三层。规则生成地形图与战略版TER，不修改原版源文件。路面视觉alpha同时生成16像素建造分类格，导航另叠加固定山石碰撞。停止渲染矢量道路层，小地图直接使用地形图。

地图1792×2048变为1920×2176（28×32格变30×34格）。原可见陆地轮廓向外扩约96像素，外围山石同幅外移，内部山石/基地/出怪口/路线不移动。有效步行边界同时更新，虚空仍禁行禁建。可建造候选格由4931增加到6968，实际塔位继续扣除完整占地碰撞。

可重复构建：work/ios-python/bin/python outputs/alien-zerg2-wechat/tools/compose-strategic-terrain.py，再运行tools/package-game.py。source-map/strategic-base为此轮转换基准，重复执行不会再次扩图。输出source-map/strategic-expanded.ter、shared/level-data.js、shared/art-data.js与assets/terrain.png。

新增native-terrain.test.js验证TER维度、合法材质掩码、运行时分类尺寸、外围可达建造点及山石碰撞。全量初跑149通过，两项旧地图尺寸和旧小程序打包断言更新为当前扩图尺寸与小游戏实际资源清单，所在13项复测全部通过。

## 2026-09-13 过渡修正
对照 `XLTerrain.cpp::UpdateTile` / `PlaceTerrain`：原版支持自带过渡图集与共用 alpha01 两套路径。当前 t04/t05 虽为 512×256，却完全不透明，不能依宽度直接按过渡图集切片。编译器现在对这两张材质使用全局 UV 平铺、alpha01 的 mask-1 四角遮罩；t06 保留自带 mask 图块及右侧完整地面。道路与可建造区域掩码由合成前的实际 alpha 生成。新增 terrain-transition.test.py 验证 28 种材质过渡、全局 UV 及 14 种道路过渡。TER 是编译输入，原版旧渲染器仅凭宽度判定的路径不会自动获得本修复。

### 后续修正：不透明不代表整张图可连续平铺
用户截图暴露了上轮规则的第二个错误。放大 t04/t05 后可见：左侧 256×256 含有预着色的四角过渡块，即使 alpha 全为 255，也不能用作连续材质；右侧 256×256 才是完整地面。修正为所有泥地/岩土图块都使用 `(256 + x%4*64, y%4*64)`，边缘再应用共享 alpha01。禁止之前的 `x%8` 全图平铺。新增 64 个完整地面采样断言。构建掩码未改变，路线、碰撞和建造回归 6 项通过；已重新渲染炼油厂周边区域检查。
