# 0030 密集战斗逻辑优化

用户授权优先改善密集怪物性能，沿用修好后发布体验版流程。存档 KEY/云 epoch 保持 20261009-0028。

## 改动

- 主/wolf Navigation.occupied：射线障碍查询使用数字网格，避免每次采样创建坐标字符串并哈希查 Set。越界仍回退原 Set 查询。wolf 补齐主版本已有的 cells setter/add/delete/clear 同步机制，地形变化立即生效、失效寻路缓存。
- 主版本直射弹每次推进只计算一次扫掠 AABB 和自身半径，所有候选敌人复用；保留目标遍历顺序、巨型怪专属碰撞区、穿透与击退。
- wolf 寻敌同步主版本平方距离和直接列表遍历，避免全量数组复制及无关目标昂贵视线检查。
- 未改变怪物数量、攻速、伤害、碰撞尺寸、AI 更新频率。没有增加大图缓存。

## 测量

work/bench-dense-combat.cjs 初步场景：160 敌人/24 机枪塔，600 帧；寻敌约 66ms，机枪视线约 42ms（包含关系，不能相加）。优化后视线约17ms。寻路仅约3ms，所以本轮未改 A*。
尝试过塔寻敌空间分桶，但此聚集场景频繁回退，建桶开销抵消收益，已删除此尝试，最终未启用分桶。
work/compare-dense-combat.cjs：预热2轮、采样6轮，每轮1200帧。每帧逻辑耗时的轮次中位数原0.586ms，现0.503ms，约下降14%。这是本机纯逻辑压力测试，不含绘制，不代表手机 FPS 提升14%。
